# DECISIONS

## Решение 1. Все правила и пороги — константами в одном месте
Границы (1…10 000, цена ≤ 5 000 000, скидка 0…30) и ставка НДС (`VAT_RATE`) заданы
`public static final` константами в `OrderCalculator`. Ни проверка, ни расчёт, ни тексты ошибок
не содержат «магических чисел». Изменение варианта (ставка НДС или максимальная скидка)
сводится к правке одной строки; SelfCheck при этом указывает, какие границы нужно обновить в тестах.

## Решение 2. double для денег с округлением до копеек на каждом шаге + единая проверка
Тип `double` выбран по условию работы (цена — дробная, до 5 млн). Его ограничение: двоичное
представление не точно хранит десятые/сотые (0,1 + 0,2 ≠ 0,3), поэтому результаты каждого шага
(после скидки, НДС, итог) округляются до копеек через `round2`, а сравнения в тестах идут с допуском.
В реальной бухгалтерии следует применять `BigDecimal`. Валидация вынесена в `describeError`/`isValid`
в форме `!(x >= min && x <= max)`: такая запись отвергает также NaN и Infinity. Разбор строк
(`parseInt`/`parseDouble`) возвращает `null` при пустом/неверном формате, поэтому ошибка контролируемая,
а расчёт не запускается.
